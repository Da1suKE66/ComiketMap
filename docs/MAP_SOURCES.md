## 重绘与裁切方法

`lib/venue.ts` 保存独立绘制的馆区轮廓、楼层、连接通路和参考链接。全场关系按 C109 第 2 页方向：东馆在左，西馆在中右，南馆在上方；西／南企业馆位于 4F。拓扑用右侧分图显示上层；3D 可切换楼层或分层展开。

`scripts/maps/extract-references.py` 从下载到 `tmp/pdfs/` 的原始 PDF 渲染各馆参考图。保持比例，以最长边约 2400 像素输出无损 WebP；西 4 图在原企业手册的两个页面间拼接。没有生成虚构的桌列替代原图。页面提供原始 PDF 与页码，方便核对裁切外的说明。

`public/maps/provenance.json` 记录原始 PDF 的 SHA-256、响应、页数和各底图的尺寸及 SHA-256。它与截图、实读 PDF 共同构成本次来源记录。

重新生成（下载文件名须与脚本一致）：

```sh
python3 -m pip install PyMuPDF Pillow
python3 scripts/maps/extract-references.py
```

## 路线范围

- 东入场和西南入场均可直接点选为当日起点，并随 JSON 保存。标记表示入场方向，不是准确的检票口／队尾，未计算到场前排队、券种与时间资格。入场起点只有进入场内的边，不能作为跨馆捷径。
- 西／南 → 东默认通过“西 1 馆口 → 西 1 外侧出口 → 过街点 → 东馆背面／货车场 → 东馆侧通道 → Galleria”这一用户参考动线；2F 室内联系桥保留为可选择的备用建筑连接。该策略只作用于西南到东的段落，不自动推断反向也允许过街。
- 西 1 馆内到外侧出口的段落用虚线表示出口关系，不是桌间导航；东馆背面的侧通道也是简化关系，开会后的准确通行口、过街位置与单向规则待 C109 公告确认。C109 第 2 页明确写“東西移動お勧めルート 7:30～9:00（道路横断時、車両に注意）”，不能把这一社团入场时段直接当作全天普通参加者路线。
- 图节点包括馆口、Galleria、中庭、2F 桥／连廊、4F 回廊及垂直换层点。
- 每条线段经过已定义的图边；施工中的东 4–6 不进入图，东 8 仅展示用途而不作为购物馆目标。
- 图上的距离只是简化图面单位，不能解释为米或步行分钟；不输出 ETA。
- 可保存每日目标顺序；生成时优先个人等级，在同等级中比较馆口间图路径。粉丝数不会自动覆盖个人优先级。
- 到达摊位目标时只规划到所属馆口，未把手动落点直线穿过桌列当作步行路径。下一阶段需要单馆通道图和底图校准。
- C109 第 2 页蓝色箭头标的是社团入场时段路线，未照搬成普通参加者的全天路线。入场券队列、临时单向、封闭和排队时间仍以当日指引为准。
- 3D 尺寸、高度及馆体细节是阅读用简化，不是建筑 CAD 或精确测绘。

## 旧手帐兼容

原示意图中的手动坐标保留在 JSON 中，未删除记录。缺少新地图版本 `venue-2026-v1` 的位置会提示重新确认；在官方底图上重新定位后才显示为当前落点。自购、代购、图片与文件绑定继续使用原数据。

`routePlans` 是按 `1`／`2`／`3` 分日的可选字段；旧 v1 手帐仍可打开。删除摊位或修改参加日时，会清理失效的路线引用；导入时拒绝引用其他活动日或不存在目标的路线。

路线的 `start` 支持两个入场分区和原有馆内起点；可选 `transfer` 为 `west1-outdoor` 或 `indoor`。缺少此偏好的旧路线按室外参考策略读取，不会因新增字段而拒绝旧手帐。
