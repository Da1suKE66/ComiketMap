## 重绘与裁切方法

`lib/venue.ts` 保存独立绘制的馆区轮廓、楼层、连接通路和参考链接。全场关系按 C109 第 2 页方向：东馆在左，西馆在中右，南馆在上方；西／南企业馆位于 4F。拓扑用右侧分图显示上层；3D 可切换楼层或分层展开。

`scripts/maps/extract-references.py` 从下载到 `tmp/pdfs/` 的原始 PDF 渲染各馆参考图。保持比例，以最长边约 2400 像素输出无损 WebP；西 4 图在原企业手册的两个页面间拼接。没有生成虚构的桌列替代原图。页面提供原始 PDF 与页码，方便核对裁切外的说明。

`public/maps/provenance.json` 记录原始 PDF 的 SHA-256、响应、页数和各底图的尺寸及 SHA-256。它与截图、实读 PDF 共同构成本次来源记录。

重新生成（下载文件名须与脚本一致）：

```sh
python3 -m pip install PyMuPDF Pillow
python3 scripts/maps/extract-references.py
```

## 入口、内部结构与路线范围

- 入口分别建模：`eastEntry2` 为正门广场的东馆方向起点，`circleEntry2` 为同一正门区域单独标识的社团票起点；`westSouthEntry4` 放在南 3／4 侧的 4F 门厅。位置按用户指明的进馆方向校正，建筑关系由上述官方图交叉核对。
- 这些标记表示入馆后的路线起点，不是候检区、队尾、精确检票口或券种资格。C108 东地区受付停车场与正门建筑入口是不同概念；不要把分区等待图等同于楼内门口图。社团票入口仅供相应持证参加者。票种、时间及临时改道仍需当届公告确认。
- 南馆补上 2F ↔ 4F 的内部扶梯联系。去南 1/2 可以在南馆内下到 2F 再下至 1F；去南 3/4、西 3/4 时可保持在 4F，避免多余的跨馆折返。
- Galleria 分 1F 和 2F 两条走廊；2F 有沿线多处下至 1F 的连接，不再把整座东馆简化成只有一个下楼点。
- 东 1、2、3 每馆都有独立的 **Galleria 侧门和背面货车场侧门**。背面门位于两侧相对的另一条立面，轮廓按官方建筑图重绘，坐标为代表门点，不对应特定开放门编号。
- 西／南 → 东 1–3 的默认室外路线是“西 1 馆口 → 西 1 外侧出口 → 过街点 → 背面货车场 → 目标馆背门”。到达东 1 就在东 1 背门结束，到东 2／3 继续沿背面货车场到各自背门；不绕侧面，不返回 Galleria 再进入目标馆。东 7 单独按建筑连接规划，不套用东 1–3 的背门策略。
- 路线保存实际到达的门。下一段从同一门继续，同一馆的多个收藏也保持当前门。若随后需从背面到正面换门，视为未计算的馆内关系：灰色虚线、无方向箭头、行走动画在这一段隐藏；不会宣称直线穿过桌列可走。西 1 馆内到外侧出口也采用这一表示。
- 可选择 2F 联系桥作为备用建筑连接。此策略与西南 → 东的室外策略分开，不推断反向过街的开放状态。
- 图上的距离只是简化图面单位，馆内换门的附加代价只用于避免无意义的选门折返，不能解释为米或分钟；不输出 ETA。
- 可保存每日目标顺序；生成时优先个人等级，在同等级中比较实际选用馆门的图路径。粉丝数不会自动覆盖个人优先级。
- 施工中的东 4–6 不进入路线图，东 8 仅展示用途而不作为购物馆目标。没有使用摊位落点生成穿过桌列的路线。
- C109 第 2 页标注的“東西移動お勧めルート”限 7:30–9:00 的社团入场时段，未据此假定普通参加者全天可通行；活动开放的门、过街点、队列和单向仍以当日引导为准。
- 3D 尺寸、高度及馆体细节是阅读用简化，不是建筑 CAD 或精确测绘。Big Sight 建筑图只用作结构事实核对，不将其原图或变形图再发布为资产。

## 旧手帐兼容

原示意图中的手动坐标保留在 JSON 中，未删除记录。缺少新地图版本 `venue-2026-v1` 的位置会提示重新确认；在官方底图上重新定位后才显示为当前落点。自购、代购、图片与文件绑定继续使用原数据。

`routePlans` 是按 `1`／`2`／`3` 分日的可选字段；旧 v1 手帐仍可打开。删除摊位或修改参加日时，会清理失效的路线引用；导入时拒绝引用其他活动日或不存在目标的路线。

旧 `eastEntry1` 自动迁移为 `eastEntry2`，旧 `westSouthEntry2` 自动迁移为 `westSouthEntry4`；原有目标顺序、购买、图片及本地文件绑定保留。迁移后的起点随下次修改写回 JSON。

路线的 `start` 支持三个独立入场方向和原有馆内起点；可选 `transfer` 为 `west1-outdoor` 或 `indoor`。缺少此偏好的旧路线按室外参考策略读取，不会因新增字段而拒绝旧手帐。
