# ComiPath · C109 参展手帐

用于 Comic Market 109 的个人摊位记录、场馆地图与代购清单。中文界面，适配桌面与手机。网页公开访问，无需 ChatGPT 登录。当前记录由用户手动维护，没有抓取官网摊位数据。

## 当前可用

- **3D 场馆与拓扑**：Three.js 真实 3D 视图，可旋转、平移、缩放、分层展开，展示会议棟四座倒金字塔、东／西／南馆和连廊；保留根据 C109 总图重绘的拓扑。支持 1F、2F、4F 筛选与 12 个馆独立显示。
- **官方分馆底图**：东 1 / 2 / 3 / 7、西 1 / 2、南 1 / 2 使用 C109 当届官方 PDF；西 3 / 4、南 3 / 4 企业馆暂用 C108 官方企业手册。界面显示版本和原始 PDF 链接，并展示 C109 按日不同的空区备注。
- **每日路线**：选择东入场、南 3/4 侧西南入场、社团票方向或馆内起点，添加摊位或馆口，手动排序或按个人优先级生成顺序；图路径连接 1F／2F／4F 通道。路线同步显示于 3D 和拓扑，可演示行走并导出文字清单；按日保存进同一个本地 JSON 文件。
- **手动定位**：每馆可在官方参考底图上手动落点，也可上传 JPG / PNG / WebP 底图替换。图片按真实长宽比显示。未定位摊位保留在清单中，不会依据摊位号推算坐标。
- **摊位管理**：日期、画师与サークル名称、馆区、ブロック、两位数字摊位号及 a / b / ab（企业馆改用 3–5 位企业编号）、品书发布状态、粉丝数、个人优先级、到访 / 售罄状态和备注。
- **品书图片**：每个摊位最多 15 张，预览、删除；单张原图 ≤ 15 MB，转为 JPEG 并限制长边到 2400 px 保存。
- **自购与代购**：按商品记录名称、种类、日元单价、自购数量；按对象分别分配代购数量。自购与每个对象都有独立的已购数量，支持只买到一部分。
- **对象账单**：按对象汇总计划数量、已购数量、计划金额与已购金额，导出 CSV。未知单价显示待定，不被当作已知零元；明确填写 0 才表示免费。
- **指定本地文件保存**：选择一个 JSON 文件后，摊位、图片和代购记录持续写回同一文件；可打开已有手帐、另存为、重试保存或断开文件。刷新会重新读取已记住的文件；权限过期时提示重新授权。
- **数据备份**：IndexedDB 保留恢复缓存与文件句柄；可下载额外完整 JSON 备份。导入与打开文件均先校验、预览再确认。CSV 供核对账单，不能代替完整手帐。
- **空白手帐与待补充名单**：首次打开不再填入示例。只有名称的记录可保存在“我的摊位 → 待补充”；日期、场馆与地址补齐后自动移入摊位清单。未补齐记录不参与路线或购物统计，也随本地 JSON 一起保存。旧版示例手帐仍可打开或手动清空。
- **开发计划**：网页内提供后续计划；详细任务与验收标准见 [ROADMAP.md](./ROADMAP.md)。

## 启动

需要 Node.js ≥ 22.13.0。

```sh
npm ci
npm run dev
```

打开终端打印的地址，默认 `http://127.0.0.1:5173`。

```sh
npm run typecheck
npx playwright install chromium
npm test
npm run build
```

已经安装 Google Chrome 时，可使用 `PLAYWRIGHT_CHANNEL=chrome npm test`。测试覆盖实际浏览器文件读写、文件句柄恢复、撤销权限后的失败与重试、外部改动保护、非法文件拒绝，以及分馆、图片、摊位增删改、A / B 独立账目、备份和手机布局。文件测试仅替换原生系统选择器与权限弹窗，读写、句柄和 IndexedDB 使用 Chromium 实际实现。`npm run build` 产出 Vinext / Cloudflare Worker 的生产版本；`npm start` 可在本地运行已构建的 Worker。构建与测试不需要 X、邮件或 LLM 的密钥。

## 使用顺序

1. 打开网页，无需登录；点击“选择保存文件”，在系统窗口指定位置，默认文件名 `ComiPath-C109.json`。已有手帐可点“打开已有手帐”，确认后绑定该文件。
2. 新手帐从空白开始。添加已知摊位，或在“我的摊位 → 待补充 → 添加名字”保存信息尚未公布的画师。已有旧版示例时，可先下载备份再清空。
3. 添加代购对象，或在摊位的“购买与代购”中快速新建对象。
4. 添加摊位，填写日期、馆区、区域与摊位号。没有品书时选“暂定 · 等待品书”。
5. 在“品书图片”上传图片；在“购买与代购”添加商品，分别填写自己、A、B 的数量。
6. 在详情中点击“地图定位”，进入对应馆点击落点；有实际平面图时先上传底图，再核对落点。
7. 当天在购买清单填写已购数量。对象页面的“已购金额”按实际买到的数量汇总，可导出 CSV 核账。
8. 确认页顶显示“已写回 文件名”后再关闭。换设备或域名时，打开同一份 JSON 文件即可恢复；也可下载额外备份。

### 例子

一本新刊单价 ¥1,000，自己买 1 本、A 买 1 本、B 买 2 本：

| 对象 | 计划数 | 已购数（示例） | 计划金额 | 已购金额 |
| --- | ---: | ---: | ---: | ---: |
| 自己 | 1 | 1 | ¥1,000 | ¥1,000 |
| A | 1 | 1 | ¥1,000 | ¥1,000 |
| B | 2 | 1 | ¥2,000 | ¥1,000 |

总计计划 4 本、¥4,000；实际已购 3 本、¥3,000，B 还差 1 本。各对象始终保持独立记录。

C109 PDF 还说明：第三日无 イ 区及东 7 的 N／O 区；三天均无 ア 区 89–92；西区还有指定空号和第二日无 き 区等。原图完整备注及按日提示均应核对，不能用 C108 参展名单推断 C109。

本项目没有抓取完整社团或企业记录。内置地图是从官方 PDF 对应页截取的参考图，所有收藏仍由用户维护。底图版本、页数、来源与 SHA-256 见 [地图来源说明](./docs/MAP_SOURCES.md) 和 `public/maps/provenance.json`。

**3D 是独立制作的简化空间模型**：按官方总图的相对位置、楼层及连接关系组织场馆；建筑高度、厚度和比例用于阅读，不是 CAD、测绘模型或精确的米制坐标。拓扑右侧单独显示 4F 企业馆，避免误认为它们和同人馆处于同一层。

**入口与内部楼层**：西南入场位于南 3／4 侧的 4F 门厅；正门广场分别标识东入场和社团票入场方向。可以点选为当日起点。补上南馆 2F ↔ 4F 扶梯、Galleria 上层走廊及沿线多处 1F 下降连接。结构交叉核对 [Big Sight 东馆建筑图](https://www.bigsight.jp/organizer/facilities/pdf/E_E_all.pdf)、[南馆建筑图](https://www.bigsight.jp/organizer/facilities/pdf/E_S_all.pdf) 与 [Comiket 内部指南](https://harenohi.comiket.co.jp/index.php/beginnersguide/generals/guideonsite/)。入口标记表示用户指明的进馆方向，不是精确检票口或等待队列；不能据此推断所有券种的入场资格。

**西南 → 东 1–3**默认采用“西 1 外侧出口 → 过马路 → 背面货车场 → 对应馆背面入口直接进馆”。东 1、2、3 分别有背面门和 Galleria 侧门，到达目标馆后立即结束该段，不绕侧面返回 Galleria。下一站从实际到达的门继续。2F 联系桥保留为备用建筑连接；东 7 独立规划。馆内换门以灰色虚线表示未计算的桌间路径，无导航箭头或行走演示，具体开放门和活动通行规则仍需现场确认。

**路线当前走到馆口**：使用带楼层的通道图和 Dijkstra 最短路径，支持手动顺序与按优先级生成。绘制 1F／2F／4F 的换层段，排除施工馆；不计算馆内桌间路线、排队时间、入场券等待队列、临时单向与封闭，也不输出无依据的米数或 ETA。C109 PDF 的蓝色箭头是社团入场时段路线，没有直接当作普通参观者全天路线使用。

此前泛化示意图上的位置会保留在记录内，但标注为“旧版位置待复核”。请在新的官方底图重新点选；重新定位后写入地图版本。换馆仍会清空落点。既有 v1 JSON 手帐可继续读取，路线与地图版本都是兼容增加的可选字段。已保存的旧入口 ID 会自动迁移到修正后的入口，目标顺序与采购数据保留。

## 本地文件与隐私

- 页面公开访问，无 ChatGPT 登录、应用账户、服务器数据库或业务数据上传接口；每位访问者使用自己的设备文件。
- 直接写回文件使用浏览器 File System Access API。请使用桌面版 Chrome / Edge，并在系统文件选择器中指定保存位置、授予权限；网页无法静默指定任意磁盘路径。见 [Chrome 官方说明](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)。
- 默认名称 `ComiPath-C109.json`；不要求特定目录。可选桌面、文稿或你自己的文件夹。网页只能显示文件名，不能显示完整本地路径。
- 每次修改串行写入，只有写入并关闭文件流成功后才显示“已写回”。品书和底图一起保存在 JSON 中；缓存成功不代表文件成功。
- IndexedDB 仅保留恢复副本和文件句柄。清除网站数据不会删除已经写入磁盘的 JSON，但会清除位置记录；重新“打开已有手帐”即可。
- 刷新时有读写权限会读取磁盘文件；权限未保留则显示重新授权。若发现缓存有较新的未写回修改，会保留缓存，要求另存为或确认重新读取文件，避免静默丢失。
- 文件被其他程序修改后，会依据文件大小与修改时间阻止自动覆盖，要求重新打开或另存为。此机制不是多进程事务锁，不替代多标签页冲突合并；建议单标签页编辑。
- 权限被撤销、文件被移动 / 删除、磁盘写入失败时，不显示保存成功，可重试、另存为或下载额外备份。断开文件只停止绑定，不删除磁盘文件。
- 不支持文件选择器的浏览器仍可体验和下载 / 导入备份，但不能自动覆盖指定文件，界面会明确提示换用支持的浏览器。
- 本地预览和线上地址的权限与缓存相互独立；在另一来源打开同一 JSON 文件即可迁移。
- 手帐文件与备份上限 60 MB，完整校验版本、字段、日期、馆区、ID、对象引用、数量、图片与坐标；可选的 `boothDrafts` 保存未补齐的名单，不能被路线引用。
- 对象仍被商品引用时禁止删除，先移除代购条目；删除摊位会一并移除其商品、图片和代购记录，并写回已绑定文件。
- Google Fonts 用于字体，加载失败回退系统字体。离线刷新 / PWA 尚未实现；页面成功加载后的编辑与文件保存均在本地完成。内置官方底图随网页提供，用户上传的品书与自定义底图才嵌入手帐 JSON。

## 结构

```text
app/                    页面入口、全局样式与元信息
components/planner.tsx  导航、筛选、购买台账、对象与备份流程
components/venue-map.tsx 3D / 拓扑 / 官方分馆底图切换
components/venue-scene.tsx Three.js 模型、旋转、分层与路线演示
components/route-planner.tsx 每日目标、顺序、起点和文字导出
lib/venue.ts            官方参考来源、馆体几何与楼层通道图
lib/routes.ts           图路径、每日优先级顺序与失效目标清理
public/maps/            12 个官方参考底图及来源校验信息
components/booth-*.tsx   摊位编辑与详情、品书图片管理
lib/model.ts            类型、Zod 校验、数量 / 金额计算与 CSV 导出
lib/db.ts               恢复缓存、文件句柄与图片转换
lib/local-file.ts       本地文件选择、校验、读写及外部改动检测
lib/use-notebook.ts     串行自动保存、权限恢复和文件切换
lib/demo.ts             仅供测试导入的虚构示例（不在首次启动时载入）
tests/                  数据规则与浏览器流程测试
scripts/ + worker/      Vinext / Sites 构建和部署支持
ROADMAP.md              六级后续开发计划
```

本项目是个人规划工具，与 Comiket 主办方无隶属关系。画师及品书图片由用户自行记录。
